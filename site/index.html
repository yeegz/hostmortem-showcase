It was fine, then it wasn’t, then someone rebooted it.
Hostmortem keeps the minutes before.

A recorder for Linux gateways and edge boxes. It writes kernel, network and service evidence to disk, survives the reboot, and answers with what it knows, what it suspects and what it could not see.

Install

Ubuntu 22.04 or 24.04, Debian 12 or 13, Raspberry Pi OS (64-bit). amd64 and arm64. Needs sudo.

curl -fsSL https://github.com/yeegz/hostmortem/releases/latest/download/install.sh | sudo sh

It checks the package against the release’s SHA-256 sums, installs it with apt and starts the hmd service. Re-run it to upgrade; your evidence is kept.

  1. sudo hm drillrecords a harmless test incident: a process killed with SIGKILL, seen by the live agent
  2. sudo hm explain 1the diagnosis: what it knows, what it suspects, what it could not see
  3. sudo hm reportevery incident as one self-contained HTML file to open or send (--redact hides addresses)

How it records

  1. Watches five places

    procfs counters, link and route changes over rtnetlink, the kernel log, a few active probes, and the processes you name.

  2. Writes evidence, not dashboards

    One writer commits batches to SQLite in WAL mode. If something is dropped under load, the drop itself is written down.

  3. Orders time it can trust

    Boot order first, then the kernel’s boot clock. Wall time is only for display, because edge boxes often wake up in 1970.

  4. Argues with itself

    Twelve playbooks score evidence for and against. If two explanations tie or nothing qualifies, the answer is “unknown”.

Measured, with the script that measured it

Lab, throughput and durability: an Ubuntu 24.04 arm64 container on an Apple M1 Pro. Install and memory: the installed service on fresh Debian 12 and Ubuntu 22.04/24.04 VMs, amd64 and arm64. Not a Raspberry Pi yet.
